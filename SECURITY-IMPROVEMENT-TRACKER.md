# Security Improvement Tracker

## 2026-10-16 — Cycle 173: restrict source-run production file permissions

- **Finding:** The source-run production instructions use `npm start`, which imports the server without first restricting POSIX file creation. With a common umask such as `022`, a fresh data directory and files created beneath it can be traversed/read by unrelated local accounts. The documented copied `.env` can also retain group/world-read permissions. Such local reads can bypass HTTP authorization and expose course media, learner data, backups, and configured secrets.
- **Root cause:** `scripts/start.js` set `NODE_ENV` and immediately imported the application; Node inherited the launching account's umask. The server creates SQLite and media storage with default filesystem modes.
- **Patch:** `scripts/start.js` now calls `secureProductionRuntimePermissions` before importing the server. On POSIX production startup it sets umask `077` and changes an existing regular default `.env` file to mode `0600`. It skips symlinks, missing dotenv files, and externally managed `DOTENV_CONFIG_PATH` paths; development and Windows are unchanged. The installer and container retain their existing permission controls.
- **Why it helps:** Newly created source-run production directories and files are owner-only, and the dotenv secrets are not group/world-readable. This is a local filesystem confidentiality fix; it does not bypass the app's remote authentication model.
- **Validation:** `node --test tests/security/production-permissions.test.js` passed 6/6 and `npm run typecheck` passed, covering startup order, private umask, default `.env` mode, symlink/missing-file behavior, externally managed dotenv paths, and chmod failure. The full `npm test` suite still has 12 unrelated existing failures in course/quiz UI assertions, search landmarks, and legacy migration fixtures. Existing files/directories are not retroactively chmodded. No POSIX production host was available for runtime verification.
- **Scope:** Conditional on POSIX source-run production with a permissive host umask and another account able to traverse the checkout/data path. Installer systemd configuration already uses `UMask=0027`; Docker paths have their own ownership and mode setup. The repository-wide scan remains partial, and live host permissions are unknown.
- **Commit title:** `fix(security): restrict source-run file permissions`.
- **Commit description:** `Set a private umask before production server startup and tighten a regular dotenv file so source-run storage and local secrets are not exposed to unrelated POSIX accounts; cover startup ordering and permission handling with focused security tests.`

## 2026-10-16 — Cycle 172: withhold quiz explanations from learners

- **Finding:** The learner course API serialized quiz explanations before an attempt. A learner who already had legitimate course access could retrieve answer rationale directly from `GET /api/courses/:courseId`, even though the learner UI did not display it and the API omitted correct-answer flags.
- **Root cause:** The course payload builder gated `isCorrect` on `includeAnswers` but copied `question.explanation` into every response.
- **Patch:** `server/course-service.js` now includes the explanation only when `includeAnswers` is true. Manager routes retain the existing `requireStaff` and `requireCourseManager` checks. `tests/server/quiz-attempt-results.test.js` asserts that the learner response omits an answer-revealing explanation and the manager response retains it.
- **Why it helps:** Learners can no longer use the API response to obtain author-provided answer rationale before submitting a quiz. The finding is an assessment-integrity disclosure to an authorized course viewer, not a course-access bypass.
- **Validation:** `node --test tests/server/quiz-attempt-results.test.js` passed 8/8 and `npm run typecheck` passed on the updated branch. `git diff --check` passed. `npm test` still reports 12 existing failures in course/quiz UI assertions, search landmarks, and legacy migration fixtures. Production deployment and external reachability were not tested.
- **Scan:** Repository-wide Codex Security Standard scan `6055fd7b-55cd-4160-a7d1-b649ab4fc2c7`, bound to working-tree snapshot `codex-security-snapshot/v1:sha256:983c7b66219d9b163d2f0d107d7d65bb74ef0055565577a777d6d8a0d50b69c6`. Coverage is partial; active deployment, filesystem, secret, proxy, TLS, firewall, and external-reachability settings remain unknown.
- **Commit:** The quiz fix is already included in the existing branch commit `1f6565a` (`feat(courses): add groups and randomized final exams`), which is now at `origin/main`. This run did not create a separate security commit for it.
